# AGENTS.md

Rules for anyone — human or agent — changing this repository. Read
[docs/requirements/](./docs/requirements/) and [docs/architecture.md](./docs/architecture.md) before
changing behaviour.

## Working rules

1. **CI actions are pinned to a full 40-character commit SHA**, with the released version in a comment:
   ```yaml
   uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4.4.0
   ```
   Never a tag, a branch, or a major-version ref. Dependabot keeps the pins current; do not unpin them to
   "get the latest".
2. **Never weaken the NFR-2 controls** — loopback binding, Host check, token plus Origin, session-id
   validation, path containment. If you touch them, add or extend a test that proves the guard still
   rejects the bad case, and say which one in the pull request.
3. **Behaviour changes need a test.** Use `node:test`; do not add a test framework, fixtures library or
   mock library. Pure logic that can live in `ui/src/lib/*.ts` runs directly under Node.
4. **The backend keeps zero runtime dependencies.** Node standard library only. A new UI dependency needs
   a reason in the pull request; prefer writing the small thing.
5. **Migrations are forward-only.** A database created by an older version must still open. Extend the
   legacy-schema test in `parked.test.js` when the schema changes.
6. **Requirements and code change together.** Update the relevant `FR-*` or `NFR-*` in the same pull
   request and cite the IDs in the description. A stale requirement is a bug.
7. **Never commit** the database, `node_modules`, `ui/dist`, personal paths, work email addresses, or
   employer names. Test fixtures use neutral values (`/Users/x`, `acme`, `example.com`).
8. **Commits and pull requests.** Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`).
   Every change lands through a pull request; `main` stays releasable. No rebases or force-pushes of a
   shared branch.
9. **Scope is explicit.** macOS, opencode, Ghostty and iTerm, one user per machine. Adding a platform, a
   harness or a terminal means requirements, implementation and tests, not a quiet extra branch.
10. **No new outbound calls.** The app may call `gh`, `git` and `npm`. No telemetry, analytics or
    remote config — see NFR-1.
11. **Installer changes ripple.** If you change install, update or the login agent, update
    `docs/architecture.md` in the same pull request, and keep any companion integration documentation
    you maintain in sync.

## Commands

```sh
npm test            # backend, installer and UI helper tests
npm run build       # install UI deps, type-check, build ui/dist
npm run dev         # Vite dev server on :5173, proxying /api to :4747
node web.js         # dashboard on http://127.0.0.1:4747
node install.js --dry-run          # show installer changes without writing
node install.js --service          # install the login agent
node install.js --service-remove   # remove it
```

Requires Node 22.5+ (developed on 24). `node:sqlite` is still flagged experimental, hence `--no-warnings`
in the test script.

## Where things live

- `docs/requirements/` — what the product does and what must stay true.
- `docs/architecture.md` — how it does it, module by module.
- `ui/` — the dashboard; `ui/src/components/ui/` is generated by `npx shadcn@latest add`, do not hand-edit it.
- Hooks live in `ui/src/hooks/`, formatting logic in `ui/src/lib/` (keep it testable and framework-free).
